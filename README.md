## 🛠️ How I build
I run AI agents like a small engineering team. I own scope, review and the release decision. The agents do the typing. 🤖

- ✍️ **Hands-on builder:** VS Code + Claude Code. I drive one task at a time.
- 🎼 **Delegated builders:** Conductor. Parallel agents, each on its own branch.
- ⚡ **Typing helper:** Copilot, for inline autocomplete only.
- 🏛️ **Source of truth:** GitHub (private repos). Branch, pull request, review, merge.
- 🗄️ **Data layer:** Neon (Postgres) for web apps, Supabase for mobile.
- 🦀 **Tooling:** Rust, for small checks and CLI tools.

**Flow:** 🧑‍💻 You → 🔨 VS Code / Conductor → 🏛️ GitHub PR → 🗄️ Neon / Supabase

**🔄 How it operates**

🎯 I write the intent: the problem, the constraint, what "done" looks like.
🌿 An agent builds it on a branch, never on main.
🔍 It opens a pull request. I read the diff before anything merges.
✅ I merge. Then every copy of the repo pulls the same version.

## 🛡️ Guardrails: human in the loop

- 🔐 **Secrets stay out of git.** Keys live in a private `.env` and never in the repo.

- 🚫 **No agent writes to `main`.** Every change goes through a branch and a pull request.

- 👀 **Human review before every merge.** I read each diff, and I'm the only one who can approve it.

- 🧑‍⚖️ **I make the release call.** Agents propose. I decide.

💡 **What this is for**

I build to learn. A working version answers more than a document, and it gives engineering a codebase and context instead of a spec dump. 📦
